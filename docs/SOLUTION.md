# TeacherLens / 教育行业方案

## 需求来源与证据状态
行业交流线索：非标准化学生作答识别困难、不同教师对参考答案的使用方式存在差异。以上为待教师侧验证的产品假设，不披露访谈对象及原始材料。V0.1 聚焦第二个问题，先使用转写文本，隔离 OCR 干扰。

## 方案决策
以初中语文阅读理解为切口，输入文本、题目、参考答案及教师评分量规，使用最多三个边界案例确认意图。每个得分点对应可核验的作答证据，程序确定性求和，教师保留最终决定。修改分为单次确认、候选规则、技术 Badcase，不自动学习。原型中校准选项仅演示规则开关；真实教师档案、多任务自动规则提取及版本回归留到后续。

## 平台复用
千问办公：计划在客户端导入单 Skill，验证文件读取、执行流程及导出；本仓库的 Python CLI/API 为独立验证环境，并不是官方插件。钉钉：未来在组织授权及接口可用前提下连接家校本和教师工作台。现阶段不需要班级身份数据或外部 API 写入。专家套件的正式打包规范需客户端确认。

## JD 对应产出
- 挖真问题：访谈与任务观察提纲（POC.md）；实际访谈未完成。
- 需求抽象：先验证评价意图，暂缓 OCR、全学科和家校通知。
- 技术可实现：Skill 文档、可运行本地演示、可选真实模型接口、确定性评测脚本。
- 闭环：教师确认与反馈记录可操作；自动规则沉淀、实测验证待下一阶段。
- 可复制：安装说明、匿名样本、评测规范。第二位真实教师复用尚未验证。

## 下一阶段
教师访谈→确认评分规范→客户端安装试验→真实模型同源评测→教师试用→一次证据驱动的版本迭代。若量规基线已经足够好，则取消额外校准步骤。
